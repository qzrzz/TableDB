- [x] **脏字段跟踪 (Dirty Field Tracking)**:
  - 机制：在写入/更新时分析字段类型，记录是否包含 Array 或特殊值 (Infinite, NaN)。
  - 存储：元数据存储在 `_schema_dirty_{tableName}` 表中，并在启动时加载到内存缓存 `dirtyFieldCache`。
  - 优化：`analyzeQueryCompatibility` 在生成查询策略时会检查缓存。
    - 如果字段未被标记为 `hasArray`，则 `Implicit array...` 检查通过，允许 SQL 策略。
    - 如果字段未被标记为 `hasSpecial`，则 Range Operator (`$gt` 等) 允许 SQL 策略。
  - 效果：对于绝大多数“干净”的标量字段，即使进行隐式查询或范围查询，也能完全走纯 SQL 路径，避免 HYBRID 模式，性能提升显著 (100ms -> 10ms)。
  - [x] **点号路径优化 (Dot Notation Optimization)**:
    - 机制：对于 `a.b.c` 这样的路径，检查 `a` 和 `a.b` 是否包含数组。
    - 逻辑：如果所有前缀路径都不是数组，则认为该点号表示 JSON 对象导航，可以直接映射为 `json_extract(data, '$.a.b.c')`。
    - 效果：嵌套字段查询 (`meta.info`) 从 Hybrid 模式转为 SQL 模式，耗时从 ~100ms 降至 ~20ms。
